# 从可答失败到 V3.1 联合验收

本轮修复的具体问题是：模型已学会 JSON，却经常在证据充分时选择 search/abstain。最终在冻结的新实体合成测试上，选中 LoRA 达到 **1437/1440 严格成功、720/720 可答成功**，通过预设七门槛；三个剩余错误全部属于跨月未来证据提前作答。这里记录诊断、被否定的路线和选择依据，不把最终成绩解释为某一项改动的独立因果收益。完整当前与历史结果见 [results.md](results.md)。

## 先定位动作瓶颈

旧 V2 开发集第 600 步只答对 13/48 个可答实例；实际生成 answer 的这 13 行，值与引用都正确。进一步使用固定 seed 73、每个 split 每类动作 8 行的 64 行探索样本，分别检查自由生成和 teacher-forced 条件似然：

| 诊断 | train 探索样本 | dev 探索样本 |
| --- | ---: | ---: |
| answer 自由生成严格成功 | 4/8 | 1/8 |
| 正确前缀下值 token top-1 | 22/22 | 27/27 |
| 正确前缀下引用 token top-1 | 56/56 | 56/56 |
| 首动作 token 占剩余 NLL | 99.66% | 99.68% |

这是动作平衡的小样本诊断，不能当成完整分布成绩。正确前缀下复制成功，也不意味着被拒答的样本在自由生成时一定能复制正确。证据支持优先检查是否作答的判别，而非扩大输出上限或修补 JSON。

手算 shifted completion-only CE 与实际 `model.loss` 最大差为 7.45e-9；prompt/padding 已 mask，监督与推理模板一致，未发现标签错位或截断。动作占绝大多数**剩余 NLL**，不是测得占绝大多数梯度；本轮没有按字段分解梯度范数。因此暂停了“给动作 loss 加权”的候选改动，保留标准 next-token SFT，没有实施新损失、规则替换或推理修复。详见 [诊断方法与原始记录](../experiments/v3/diagnostics/README.md)。

## 容量对照没有解决联合目标

先只把 rank-8 LoRA 从 q/v 扩展到 q/k/v/o/gate/up/down 七个投影，可训练参数由 540,672 增至 4,399,104。保持 V2 训练数据、底模、seed=42、600 步预算、学习率轨迹及推理设置一致，在同一 168 行旧 dev 比较：

| 600 步对照 | 严格成功 | 可答成功 | 不可答时冒答 | 已答合同错误 |
| --- | ---: | ---: | ---: | ---: |
| q/v LoRA | 123/168 | 13/48 | 10/120 | 10/23 |
| 七投影 LoRA | 124/168 | 23/48 | 19/120 | 19/42 |

回答更多，但错误回答也增加，整体只多对一行；这不构成可靠性修复。该探针只用于旧 train/dev 的机制探索，没有用新 test 挑选结果。保留全部 200/400/600 输出与配置核对：[容量对照](../experiments/v3/capacity-probe/comparison.json)。在这个单种子对照中，只扩展可训练模块不足以同时改善可答率和误答风险。

## 两次静态覆盖修正

第一次从 V2 到 V3，针对实际发现的文本线索补反例：V2 中“三篇文档都提到当前产品”或“两篇官方数值相等”可成为单向 answer 标记；同组充分证据也没有同时覆盖两种预算。V3 将产品提及、社区相关性、无关官方数值关系交叉分配，并让十种语义都覆盖 budget 0/1，形成每组 20 单元。`value_changed` 只改变适用事实，保持另一官方事实不变。数据覆盖审查不是把这些诊断规则用于模型后处理。[原始 CPU 诊断](../experiments/v3/analysis-design.md)

第二次在任何 V3 模型确认前，发现 20 单元仍不足：一个不匹配问题 topic、不比较多官方事实值的规则，在 V3 train/dev 严格全对。它只需在“官方 topic 混合”或“同 scope 当前候选数不是 1”时拒答；数据缺少反例。于是保留旧 V3 冻结记录，使用新 seed **20261030** 创建 V3.1：

- `irrelevant_topic_b0/b1`：从 conflict 只改第二篇当前官方文档的 topic，应回答剩余适用事实。
- `consensus_b0/b1`：从 conflict 只改第二篇官方文档的值，使其一致，应回答并引用两个 ID。
- 原 missing 的一半组让两篇官方文档具有同一个错误 topic，反驳“官方主题相同就认为匹配问题”的修补捷径。

新数据每组 24 单元，train/dev/test 分别 80/24/60 组；与 main、V2、V3 所有 split 的 **584 个历史实体全集零重合**。新增 topic/value 干预保持其他公开字段不变；预算配对只改预算；独立审计同时检查公开目标、恢复目录、引用与实体隔离。没有更改三字段输出、原始消息投影或严格评分合同。[静态反例](../experiments/v3/train-dev-audit.md) · [V3.1 验收补充](../experiments/v31/acceptance-plan.md) · [冻结记录](../experiments/v31/freeze.json)

两条已知不充分规则在 V3.1 train/dev 都无法通过联合门槛。修补规则仍能达到 95.83% 总正确率，但过度回答 8.33%、已答合同错误 7.69%，因此被风险门槛拒绝。这个结果只否定明确的两条捷径，不证明全部潜在线索已消失。

## 组合干预与预先固定的选择

正式训练使用 Qwen2.5-0.5B-Instruct、七投影 rank-8 LoRA、标准 assistant+EOS 交叉熵；MPS/bfloat16、microbatch 1、累积 4、max_length 512、学习率 3e-4，warmup 60 后线性下降。1,920 行训练数据在 2,400 步中恰好经历五次完整采样。实际训练用时 **5568.61 秒（92.81 分钟）**；没有云计算或外部教师模型。完整配置和权重绑定见 [注册表](../experiments/v31/registry.json) 与 [选中训练记录](../experiments/v31/confirmation/selected-training.json)。

这同时改变数据覆盖、训练预算、学习率轨迹及可训练模块，**不是相对于 V2 的等预算数据消融**。能够确认的是这组改动及开发选择后的结果，不能单独将提升归因于反事实采样、参数量或训练时长。

600/1200/1800/2400 四个候选在运行前注册；同一 576 行 dev、bf16/MPS/batch 4、greedy、72 token、无输出修补。先要求严格成功、可答成功、四动作 macro F1、整组成功、过度回答、格式、已答合同风险七项全过，再依次按可答、整组、总体、风险与注册顺序排序。无合格候选则禁止 test。[协议](../experiments/v31/protocol.json)

| checkpoint | 严格成功 | 可答成功 | 整组成功 | 过度回答 | 已答合同错误 | 联合门槛 |
| ---: | ---: | ---: | ---: | ---: | ---: | --- |
| 600 | 334/576 | 125/288 | 0/24 | 72/288 | 73/198 | fail |
| 1200 | 380/576 | 95/288 | 0/24 | 3/288 | 3/98 | fail |
| 1800 | 570/576 | 287/288 | 20/24 | 5/288 | 6/293 | pass |
| **2400** | **576/576** | **288/288** | **24/24** | **0/288** | **0/288** | **pass，选中** |

1200 的低误答比例伴随过低覆盖，回答数 98 小于资格要求 231，风险项也不算通过。它在普通四类可答情境的 192 行全部错误 search/abstain，却在两个新增 scope 配对超过 90%；不能只展示好看的配对指标。1800 修复普通情境后，仍有五个未来日期误答与一个错引社区文档；2400 在 dev 修复全部六行。四候选同属一条训练轨迹，不能当成四次独立重复。[独立开发分析](../experiments/v31/dev-analysis.md)

## 一次最终确认及未解决边界

模型在测试前固定为 `crossed-r8-step2400`；唯一正式确认在 60 个新产品组、1,440 行上取得 1437/1440 严格成功、720/720 可答成功、58/60 全组正确。两个新增配对各 120/120；全部 24 单元的分母、混淆矩阵、raw 与独立复算见 [最终分析](../experiments/v31/final-analysis.md)。

剩余三个错误均提前采用 **2026-04-01** 才生效、as_of 为 **2026-03-31** 的证据。同月未来一天 116/116 正确，跨月仅 1/4 正确，后者只有两个产品组。这是最终结果的局部弱点；事后分层只用于解释，不修改本轮门槛或重选模型。总体通过不能改写成“日期推理已可靠”。

同一 V3.1 测试上，固定 V2 adapter 为 **751/1440 严格成功、184/720（25.56%）可答成功、152/720 冒答**；当前模型分别为 1437/1440、720/720、3/720。Base 全部未通过结构协议，不能将其零分解读为知识能力为零；完整合同规则为 1440/1440。所有参考 raw 已按公共推理参数和底模/适配器指纹核对：[同集审计](../experiments/v31/reference-audit.json)、[完整结果表](results.md)。这仍不是等预算消融；旧 V2 原测试的 12.50% 可答率只保留为历史失败，不与新分布上的 100% 直接相减。

本项目仍是固定合成语法中的证据决策训练与审计：规则可完美解决该合同，SFT 的部署必要性未被证明；未验证自然文档、自由改写、长证据、多轮搜索或生产安全。未来若继续修跨月问题，这批测试已经是已见数据，需要新的开发记录和独立确认，不能将同一测试再次包装成新鲜验证。
