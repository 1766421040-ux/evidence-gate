# 选题决策：先验证证据决策，再扩大 Agent 能力

日期：2026-10-27。本文记录实现前的选择、反对证据和停止条件；它不是实验结果。

## 要解决的具体问题

管理员问“我们的审计日志保留多少天”，检索器却可能返回另一套餐、另一主题、旧版本或互相冲突的说明。模型即使能流畅作答，也可能把“检索到了文字”误当成“已有足够证据”。单纯训练更多问答对，不能直接检验它是否知道何时回答、继续检索、询问用户或停止作答。

EvidenceGate 把这个问题收缩为一个可复现的控制任务：在虚构协作 SaaS 的管理员知识库中，根据问题、当前证据和剩余检索次数，生成 `answer / search / clarify / abstain` 之一，并按结构协议提交答案和引用。核心实验是：**保持问题基本相同，只改变证据，模型是否做出正确的相应改变？**

真实 SaaS 的产品规则不进入训练集。产品、套餐、数值和文档均为本项目生成的虚构内容；这使我们能够构造反事实并保存精确真值，也明确限制了外推范围。

## 比较过的三条路线

| 路线 | 用户问题与可交付物 | 最有力的反对意见 | 决定与重开条件 |
| --- | --- | --- | --- |
| 通用工具调用 SFT | 模型把意图转换为正确函数与参数；构建工具数据、LoRA 和调用评测 | 和已有 ToolShift 的工具使用、工具变化与适配训练高度重合；若只是增加工具数量，作品集增量有限 | 暂缓。只有获得新领域的真实调用失败集，并能证明现有工具适配方案解决不了时重开 |
| 文档问答 / RAFT 式 SFT | 在检索证据中选取事实并忽略干扰，输出有引用的回答 | RAFT 已直接研究该问题；单纯更换业务文档容易成为复现，且不能单独解释拒答和澄清 | 保留为基线方向。若控制任务没有额外收益，收缩为有清晰边界的领域问答复现，不硬称创新 |
| 证据条件下的控制 SFT（选用） | 在充分、缺失、过期、冲突、无关等证据之间切换，检验回答与延迟回答的边界 | Self-RAG 已有按需检索，R-Tuning 已有拒答训练；本项目的有限世界可以被规则完整求解 | 作为工程研究作品：提供可审计的成组数据、严格评分、本机训练与真实结果。只有外部自然语言任务显示规则不足时，才讨论模型的部署必要性 |

## 和已有作品的分工

CaseDesk 的主线是售后工单工作流、审批与业务执行；ToolShift 的主线是工具语义变化及适配。EvidenceGate 聚焦**训练数据、LoRA SFT、证据依赖评测和失败分析**。不增加退款、审批、工具注册表等重复功能，也不把新增页面数量当作技术贡献。

## 可以主张什么

1. 一套以问题族为单位的数据构造和隔离方式：同组覆盖证据变化、事实值变化与无关干扰。
2. 同时衡量“该改变时是否改变”和“不该改变时是否保持”的评测协议，避免仅凭平均准确率掩盖证据不敏感。
3. 在当前电脑上完成可复现的标准 LoRA SFT，并发布数据清单、配置、原始预测和审计结果。

这些是本项目的工程设计贡献，**不是新的 SFT 损失函数、首次 Agentic RAG 或首次拒答训练**。`group_id` 用于隔离和评分；把相同训练行打乱顺序不会产生新的目标函数。

## 明确不做的推断

- 这个任务的 `search` 标签来自预先约定的恢复协议：证据不足且仍可检索时尝试一次；没有学习最优检索成本，也没有进行强化学习。
- 规则基线若获得满分，意味着当前环境可由规则解决；不能据此宣称模型比规则更适合部署。
- 合成测试提升不能证明真实企业知识库上的通用性、中文通用理解或生产可靠性。
- 格式正确率提升不等于事实正确率提升；拒答更多也不自动意味着更可靠。
- 小模型本机实验不能冒充 7B/14B 模型实验，单个训练种子不能冒充多次独立复现。

## 执行边界与判定门槛

用户授权仅使用当前 M4 Pro / 24 GB 电脑，不产生云端或 API 费用。模型权重可从公开来源下载；训练和推理留在本机。当前实验协议使用 Qwen2.5-0.5B-Instruct、标准 LoRA SFT，对比 base、answer-only SFT 与 evidence SFT。两次训练各计划 200 个 optimizer steps，有效 batch 为 4（microbatch 1 × accumulation 4），采用 bfloat16、最大长度 512 和 gradient checkpointing；监督 token 总数和样本重复次数不必相等，不能称作等 token 预算的配对结构消融。完成步数、耗时、内存是否可得及实际依赖版本以运行记录为准。

初始 float32 运行在第 67 步内存不足，已保留完成的 66 步日志；随后通过缩小 microbatch、降低精度和激活重计算适配本机。该调整依据资源失败，未根据 test 表现挑配置。失败记录与当前配置分开保存，不能拼接成一次成功训练，见 [训练说明](training.md)。

固定语法的当前规则对照已实测：`contract` 在 280 个测试实例上严格正确 280 个，`first-match` 为 140 个。前者只读可见输入，但完全针对生成语法编写；这个结果直接反对“本合成任务必须使用 SFT”的说法。原始预测见 [contract.json](../experiments/contract.json) 和 [first-match.json](../experiments/first-match.json)。后续 V1 模型实测发现了数量 / 预算捷径，未通过证据行为验收，详见 [实际结果](results.md)；这里保留实现前的路线与门槛作为审计记录。

实现按以下门槛推进：

| 门槛 | 必须留下的证据 | 未通过时的处理 |
| --- | --- | --- |
| 数据可审计 | split 无 group 交叉、生成可重现、标签未进入输入、每种变体有独立断言 | 先修数据，不解释模型成绩 |
| 训练确实发生 | 非零可训练参数、有限 loss、保存的 adapter、重载推理、模型与数据身份 | 发布失败记录或管线结果，不声称完成有效微调 |
| 评测可重放 | 同一测试集、同一解码方式的 base / SFT / rule 预测，严格评分器和失败案例 | 不发布“提升”结论 |
| 主线能被反驳 | 隐去 / 置换证据诊断，答案值变化对，以及干扰不变对 | 若只学到模板或动作先验，收缩结论并保留负结果 |
| 对外发布 | README 和结果表能逐项追溯到保存的 artifact | 没有测量的项标 `pending`，不使用计划值替代 |

## 最有可能否定主线的对照

冻结测试集后，对同一已训练模型做“当前证据 → 不相关证据”的干预，并保持问题、预算和其余格式不变，按干预后的可见证据重新评分。如果无证据输入仍能保持原来的答案，或成组严格正确率没有比强提示词的未微调模型提高，不能认为模型学到了依赖证据的控制。即使总动作准确率提高，也可能只是记住模板和类别分布。

额外的部署否定对照是规则基线：如果规则在全部合成集和人工改写挑战上均正确且成本更低，应明确推荐该有限场景使用规则；本项目仍可作为训练与评测作品，不编造 SFT 的业务必要性。

## 重新打开其他路线的条件

- **模型不如规则且自然语言挑战也无优势：** 保留规则为实际执行器，模型仅用于研究；扩大到开放文档前先获得真实失败样本。
- **只改善 JSON 格式：** 将结论缩减为协议适配；先修正数据难度和语义测试，不更换指标宣布成功。
- **事实抽取是主要瓶颈：** 单独测试带干扰的问答训练，判断是否应改走 RAFT 式路线。
- **澄清与检索长期混淆：** 检查标签能否从输入唯一决定；必要时移除不可辨识样本，不能靠隐藏元数据强行给唯一真值。
- **本机资源不足：** 缩小基础模型或上下文，保留同一协议；不启动付费云训练。
