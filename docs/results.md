# 实验结果与失败分析

这份记录区分训练完成、协议合规和证据行为。所有数字来自随仓库发布的逐条预测；没有使用云端模型、付费 API 或远程 GPU。

## V1：格式学会了，证据判断没有通过验收

底模为 Qwen2.5-0.5B-Instruct；两个 LoRA 分别训练 200 步，seed=42。两者都使用有效 batch 4、rank 8、q/v 投影和 assistant + EOS 监督。
三种模型统一使用 MPS、bfloat16、batch 4、greedy、最多 72 个新 token，不修复生成文本。

| 方法 | 严格成功 | JSON 协议合法 | 可回答样本成功 | 不可回答时冒答 | 整组全正确 |
|---|---:|---:|---:|---:|---:|
| Base | 0/280 | 0/280 | 0/80 | 不可估计¹ | 0/20 |
| Answer-only SFT | 80/280（28.57%） | 280/280 | 80/80 | 200/200 | 0/20 |
| Evidence SFT | 200/280（71.43%） | 280/280 | 20/80 | 0/200 | 0/20 |
| First-match 规则 | 140/280（50.00%） | 280/280 | 80/80 | 140/200 | 0/20 |
| 完整协议规则 | 280/280（100%） | 280/280 | 80/80 | 0/200 | 20/20 |

¹ Base 全部未通过严格解析，不能从零个合法 answer 推断安全性。它有些自然语言答案正确，如 `g0092:supported` 回答了 120 days；0 分表示没有完成本项目的结构协议，**不是知识能力为零**。10/280 条触及生成上限；大多数格式失败并非截断造成。

完整数据：[base](../experiments/base.json)、[answer-only](../experiments/answer-only-sft.json)、[evidence](../experiments/evidence-sft.json)、[规则](../experiments/contract.json)。

### 为什么 71.43% 不是成功

Evidence SFT 在 80 个可回答实例中只答对 20 个，另 24 个不必要地检索，36 个停止回答；20 个缺少套餐的问题也没有一个输出 `clarify`。它新增 180 个正确的非回答动作，同时丢失了 answer-only 原本正确的 60 个回答。

观察 V1 测试结果后的分析发现，下面的可见输入启发式与该模型的 **280/280 个动作一致**：

```text
文档数量 >= 3 → answer
否则，budget > 0 → search
否则 → abstain
```

V1 中只有 `distractor` 场景有三篇文档。是否出现那段固定注入文字也具有同样的相关性，故这不是对模型内部因果机制的证明；但其行为完全可以由浅层线索解释，不能据此宣称学会了证据充分性。

| 成组检查（两端均正确才计分） | Answer-only SFT | Evidence SFT |
|---|---:|---:|
| 事实值改变 | 20/20 | 0/20 |
| 加入干扰，答案应不变 | 20/20 | 0/20 |
| 文档重排，答案应不变 | 20/20 | 0/20 |
| 同预算删除证据 | 0/20 | 0/20 |
| 检索预算耗尽 | 0/20 | 20/20 |
| 同预算证据过期 | 0/20 | 0/20 |

Evidence 的 20 组都恰好正确 10/14，因此按组 bootstrap 区间退化为 [71.43%, 71.43%]。这反映模板化组结构，不能当成多个训练种子的稳定性证明。

### 实际训练资源

| 运行 | optimizer steps | 耗时 | 可训练参数 | 最后一批 loss |
|---|---:|---:|---:|---:|
| Answer-only | 200 | 410.17 秒 | 540,672 | 0.0000451 |
| Evidence | 200 | 389.36 秒 | 540,672 | 0.02183 |

硬件为当前 M4 Pro / 24 GB 电脑；没有产生云计算费用。loss 是 teacher-forcing 下的 token 平均值，包含大量容易学会的 JSON 格式 token；**低 loss 不等于自由生成的正确决策**。两次训练步数相同，但语料数量、回答长度和监督 token 总数不同，这不是等 token 预算的因果消融。

模型文件：[answer-only adapter](../artifacts/answer-only-lora)、[evidence adapter](../artifacts/evidence-lora)。每个目录包含模型卡与 Apache-2.0 许可证；权重与训练日志 SHA256 在 [发布清单](../artifacts/manifest.json) 中。

最初 float32 训练在第 67 步内存不足，只完成 66 步。随后改为 bf16、microbatch 1、梯度累积、固定 padding 和梯度检查点，并完成上述两次训练。未关闭 MPS 内存保护，未把失败运行与成功运行日志拼接。见 [失败记录](../experiments/failed-float32/README.md)。

## V1 诊断与真实检索闭环

改写、删除证据的数据在模型评测前生成锁定，各使用主测试前四组（56 条）；与主测试共享产品，不能作为新增独立样本。随后补充的闭环评测也使用这四组全部14变体，不按成功与否挑案例。闭环每一步必须依据当时可见证据正确决策；仅到达终态不算成功。

| 方法 | 改写严格成功 | 删除全部证据后正确动作 | 闭环严格成功 | 合法终态 |
|---|---:|---:|---:|---:|
| base | 0/56 | 0/56 | 0/56 | 0/56 |
| answer-only-sft | 16/56 | 0/56 | 16/56 | 56/56 |
| evidence-sft | 40/56 | 25/56 | 20/56 | 56/56 |

answer-only 在删除所有文档后仍选择回答；evidence 的闭环也不能靠单步总分推断成功。逐步 trace、原始文本与判定依据见 [诊断目录](../experiments/diagnostics)。这组结果未用于修改 V1 权重或重新挑选 V1 checkpoint。

## 如何复查

```bash
pip install -e '.[test]'
pytest -q
python scripts/verify_artifacts.py
evidence-gate serve --report experiments/report.json --port 8766
```

校验脚本从原始生成文本重算主报告指标、重生成合成数据并核对 adapter 和日志哈希；不需要下载底模。
实际重新训练和自由生成需要 [训练依赖及底模](training.md)。不同设备、依赖版本和训练种子可能导致差异，当前结果只支持这里的单机、单种子合成任务。

## 解释边界

- 协议规则能完整解决这个固定语法环境，应优先作为该环境的执行器。SFT 在这里用于学习与诊断，不构成部署必要性证明。
- 数据为英文合成模板，产品和政策均为虚构；没有真实企业语料、中文开放域或大规模模型上的结论。
- `search` 服从约定恢复协议，没有训练最优检索规划，也没有 RL/DPO。
- 标准 LoRA、拒答训练和按需检索已有先例；项目贡献是数据干预、审计、严格评测与可核验的实验链路。
