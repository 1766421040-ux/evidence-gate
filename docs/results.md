# 实验结果与失败分析

这份记录区分训练完成、协议合规和证据行为。所有数字来自随仓库发布的逐条预测；没有使用云端模型、付费 API 或远程 GPU。

## V2：完成独立后续实验，仍未通过质量门槛

针对 V1 的文档数量与注入模板相关性，V2 固定每条三篇文档、两篇官方与一篇社区来源，所有行共享注入尾句，使用新的产品与事实。协议先固定，数据在训练期间冻结；[V2 协议](v2_protocol.md) 解释日期平衡、检索恢复快照及剩余混杂因素。数据冻结与审计工具已在 [7ee6af8](https://github.com/1766421040-ux/evidence-gate/commit/7ee6af8069488cb67da73f53aff622ad6ef368d5) 发布，早于最终选模和测试。

真实训练在 M4 Pro / 24 GB 上运行 600 步，用时 **1322.86 秒（22.05 分钟）**。rank 8、540,672 个可训练参数；MPS / bfloat16、microbatch 1、累积 4、max_length 512、学习率 3e-4、warmup 15。最长训练样本为 492 tokens，没有截断；首步 / 末步 loss 为 1.29280 / 0.01928。完整运行日志与选中权重的记录分别发布，参见 [600 步完整记录](../experiments/training/evidence-v2-full) 与 [选中权重记录](../experiments/training/evidence-v2)。

### 先开发集选点，再测试

三个 checkpoint 使用同一 168 条 dev。固定选择指标是四种真值动作的严格成功率宏平均，精确并列选更早步数；它不是动作 macro-F1。按这个规则选中 600 步，没有根据测试结果改选 400 步。

| checkpoint | 总体严格成功 | answer | search | clarify | abstain | 宏平均严格成功 |
|---|---:|---:|---:|---:|---:|---:|
| 200 | 113/168 | 0/48 | 60/60 | 5/12 | 48/48 | 60.42% |
| 400 | 123/168 | 23/48 | 58/60 | 12/12 | 30/48 | 76.77% |
| **600（选中）** | **123/168** | **13/48** | **52/60** | **12/12** | **46/48** | **77.40%** |

600 步在宏平均上略高，但回答能力比 400 步更低。这揭示了单一选模指标的取舍；“三个候选中最高”不代表达标。dev 只有 12 个组，而且用于选择，不能作为无偏测试结论。机器可读选择、候选原始结果和 SHA256 见 [selection.json](../experiments/v2/selection.json)。

### 一次锁定测试与六项判定

测试集为 20 个新产品组、280 条。模型使用 bfloat16、batch 4、greedy、最多 72 个新 token；不修补 JSON，也不提供候选答案或标签。实际发布的权重 SHA256 为 `5af71346aa50dc90b3f7cfc130127a94e3b97c83076c84ac6503b62fb5d4c9e5`。

| 条件 | 实测 | 预设要求 | 判定 |
|---|---:|---:|---|
| 严格任务成功 | 204/280 = 72.86% | ≥ 85% | 未通过 |
| 可回答样本成功 | 10/80 = 12.50% | ≥ 80% | 未通过 |
| 四动作 macro-F1 | 0.7123 | ≥ 0.80 | 未通过 |
| 整组 14 变体全正确 | 0/20 | ≥ 50% | 未通过 |
| 不应回答时冒答 | 6/200 = 3.00% | ≤ 5% | 通过 |
| 严格 JSON 协议合法 | 280/280 | 100% | 通过 |

**最终质量门槛：fail，2/6 项通过。** 原始输出：[selected-v2.json](../experiments/v2/selected-v2.json)；严格复算与判定：[quality-gate.json](../experiments/v2/quality-gate.json)。质量门槛失败被保留，软件测试或发布成功均不能把这个 `fail` 变成模型通过。

总体成功率按产品组 bootstrap 的 95% 区间是 [70.71%, 75.00%]。它仅描述这 20 个合成组的重采样，不包含训练种子、模型规模或自然文档分布的不确定性。

### 72.86% 仍掩盖了什么

| 真值动作 | 预测 answer | search | clarify | abstain |
|---|---:|---:|---:|---:|
| answer（80） | 10 | 37 | 0 | 33 |
| search（100） | 4 | 96 | 0 | 0 |
| clarify（20） | 0 | 0 | 20 | 0 |
| abstain（80） | 2 | 0 | 0 | 78 |

模型能识别本任务中省略套餐的澄清条件，但在本应回答的场景中，46.25% 无谓检索、41.25% 停止作答。实际只产生 16 个 answer，其中 6 个无依据，**已作答中的无依据比例为 37.50%**。3% 冒答率以 200 个不应回答样本为分母，两者不矛盾；不能只展示其中较好看的数字。

四类可回答变体中，supported 为 0/20，value_changed 为 0/20，distractor 为 9/20，reordered 为 1/20。除了预算耗尽对为 20/20，其余五种成组检查均为 0/20。V2 消除了几个已知的固定特征，却没有证明模型学会了稳定的证据使用；也不能从这些输出反推出唯一的内部因果机制。

查看 V2 test 后没有启动第三轮训练或数据修改。这个版本适合用来研究数据覆盖、选择指标和模型失败，**不适合直接部署为业务问答 Agent**。后续研究需要独立自然文档验证和预先定义的新协议；当前测试结果不能继续充当调参用的开发集。

V2 同时改变数据、训练预算和学习率调度；与 V1 的差异不能单独归因于数据修正。固定 V1 adapter 在 V2 上的结果属于参考迁移检查，不能当作等预算消融。完整协议规则依旧是这个固定语法任务应优先采用的执行器。

### 同一 V2 测试集上的固定参考

四种模型使用同一基础快照与相同推理配置。两个 V1 adapter 没有在 V2 上重训；这些结果用于显示原有策略面对新输入时的行为，不证明某项设计的独立收益。

| 方法 | 严格成功 | 可回答样本成功 | 不应回答时冒答 | 整组全正确 |
|---|---:|---:|---:|---:|
| Base | 0/280¹ | 0/80 | 不可估计¹ | 0/20 |
| V1 answer-only 固定权重 | 56/280 | 56/80 | 200/200 | 0/20 |
| V1 evidence 固定权重 | 145/280 | 17/80 | 67/200 | 0/20 |
| **V2 selected-600** | **204/280** | **10/80** | **6/200** | **0/20** |
| 完整协议规则 | 280/280 | 80/80 | 0/200 | 20/20 |

¹ Base 的 280 条输出均未通过严格 JSON 协议，不能将零个合法 answer 解读为安全，也不能将协议得分为零解读为没有知识。其余三种模型和规则均通过 280/280 条格式检查。

完整逐例结果与三次训练记录见 [V2 回放报告](../experiments/v2/report.json)。报告与原始评测文件、选模记录、选中 checkpoint 和实际发布权重通过 `verify_artifacts.py` 相互核对。浮点聚合显式使用 `math.fsum`，确保不同 Python 版本重算一致；未因此放松严格比较、改动原始文本或修改已有分数。

## V1：格式学会了，证据判断没有通过验收

底模为 Qwen2.5-0.5B-Instruct；两个 LoRA 分别训练 200 步，seed=42。两者都使用有效 batch 4、rank 8、q/v 投影和 assistant + EOS 监督。
三种模型统一使用 MPS、bfloat16、batch 4、greedy、最多 72 个新 token，不修复生成文本。

| 方法 | 严格成功 | JSON 协议合法 | 可回答样本成功 | 不可回答时冒答 | 整组全正确 |
|---|---:|---:|---:|---:|---:|
| Base | 0/280 | 0/280 | 0/80 | 不可估计¹ | 0/20 |
| Answer-only SFT | 80/280（28.57%） | 280/280 | 80/80 | 200/200 | 0/20 |
| Evidence SFT | 200/280（71.43%） | 280/280 | 20/80 | 0/200 | 0/20 |
| First-match 规则 | 140/280（50.00%） | 280/280 | 80/80 | 140/200 | 0/20 |
| 完整协议规则 | 280/280（100%） | 280/280 | 80/80 | 0/200 | 20/20 |

¹ Base 全部未通过严格解析，不能从零个合法 answer 推断安全性。它有些自然语言答案正确，如 `g0092:supported` 回答了 120 days；0 分表示没有完成本项目的结构协议，**不是知识能力为零**。10/280 条触及生成上限；大多数格式失败并非截断造成。

完整数据：[base](../experiments/base.json)、[answer-only](../experiments/answer-only-sft.json)、[evidence](../experiments/evidence-sft.json)、[规则](../experiments/contract.json)。

### 为什么 71.43% 不是成功

Evidence SFT 在 80 个可回答实例中只答对 20 个，另 24 个不必要地检索，36 个停止回答；20 个缺少套餐的问题也没有一个输出 `clarify`。它新增 180 个正确的非回答动作，同时丢失了 answer-only 原本正确的 60 个回答。

观察 V1 测试结果后的分析发现，下面的可见输入启发式与该模型的 **280/280 个动作一致**：

```text
文档数量 >= 3 → answer
否则，budget > 0 → search
否则 → abstain
```

V1 中只有 `distractor` 场景有三篇文档。是否出现那段固定注入文字也具有同样的相关性，故这不是对模型内部因果机制的证明；但其行为完全可以由浅层线索解释，不能据此宣称学会了证据充分性。

| 成组检查（两端均正确才计分） | Answer-only SFT | Evidence SFT |
|---|---:|---:|
| 事实值改变 | 20/20 | 0/20 |
| 加入干扰，答案应不变 | 20/20 | 0/20 |
| 文档重排，答案应不变 | 20/20 | 0/20 |
| 同预算删除证据 | 0/20 | 0/20 |
| 检索预算耗尽 | 0/20 | 20/20 |
| 同预算证据过期 | 0/20 | 0/20 |

Evidence 的 20 组都恰好正确 10/14，因此按组 bootstrap 区间退化为 [71.43%, 71.43%]。这反映模板化组结构，不能当成多个训练种子的稳定性证明。

### 实际训练资源

| 运行 | optimizer steps | 耗时 | 可训练参数 | 最后一批 loss |
|---|---:|---:|---:|---:|
| Answer-only | 200 | 410.17 秒 | 540,672 | 0.0000451 |
| Evidence | 200 | 389.36 秒 | 540,672 | 0.02183 |

硬件为当前 M4 Pro / 24 GB 电脑；没有产生云计算费用。loss 是 teacher-forcing 下的 token 平均值，包含大量容易学会的 JSON 格式 token；**低 loss 不等于自由生成的正确决策**。两次训练步数相同，但语料数量、回答长度和监督 token 总数不同，这不是等 token 预算的因果消融。

模型文件：[answer-only adapter](../artifacts/answer-only-lora)、[evidence adapter](../artifacts/evidence-lora)。每个目录包含模型卡与 Apache-2.0 许可证；权重与训练日志 SHA256 在 [发布清单](../artifacts/manifest.json) 中。

最初 float32 训练在第 67 步内存不足，只完成 66 步。随后改为 bf16、microbatch 1、梯度累积、固定 padding 和梯度检查点，并完成上述两次训练。未关闭 MPS 内存保护，未把失败运行与成功运行日志拼接。见 [失败记录](../experiments/failed-float32/README.md)。

## V1 诊断与真实检索闭环

改写、删除证据的数据在模型评测前生成锁定，各使用主测试前四组（56 条）；与主测试共享产品，不能作为新增独立样本。随后补充的闭环评测也使用这四组全部14变体，不按成功与否挑案例。闭环每一步必须依据当时可见证据正确决策；仅到达终态不算成功。

| 方法 | 改写严格成功 | 删除全部证据后正确动作 | 闭环严格成功 | 合法终态 |
|---|---:|---:|---:|---:|
| base | 0/56 | 0/56 | 0/56 | 0/56 |
| answer-only-sft | 16/56 | 0/56 | 16/56 | 56/56 |
| evidence-sft | 40/56 | 25/56 | 20/56 | 56/56 |

answer-only 在删除所有文档后仍选择回答；evidence 的闭环也不能靠单步总分推断成功。逐步 trace、原始文本与判定依据见 [诊断目录](../experiments/diagnostics)。这组结果未用于修改 V1 权重或重新挑选 V1 checkpoint。

## 如何复查

```bash
pip install -e '.[test]'
pytest -q
python scripts/verify_artifacts.py
evidence-gate serve --report experiments/v2/report.json --port 8766
```

校验脚本从原始生成文本重算两版主报告、六份 V1 诊断、三份 V2 dev 选择与最终质量门槛，重生成两版合成数据并核对 adapter、checkpoint 和日志哈希；不需要下载底模。
实际重新训练和自由生成需要 [训练依赖及底模](training.md)。不同设备、依赖版本和训练种子可能导致差异，当前结果只支持这里的单机、单种子合成任务。

## 解释边界

- 协议规则能完整解决这个固定语法环境，应优先作为该环境的执行器。SFT 在这里用于学习与诊断，不构成部署必要性证明。
- 数据为英文合成模板，产品和政策均为虚构；没有真实企业语料、中文开放域或大规模模型上的结论。
- `search` 服从约定恢复协议，没有训练最优检索规划，也没有 RL/DPO。
- 标准 LoRA、拒答训练和按需检索已有先例；项目贡献是数据干预、审计、严格评测与可核验的实验链路。
