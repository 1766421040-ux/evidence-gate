# V3.1 条件式后续决策备忘录

**状态：备选方案，尚未触发。** 当前 2400 步训练未结束。只有四个已登记候选的完整 dev 原始输出重审后均未满足七项门槛、选择结果为 `no_eligible_candidate`，才启用本备忘录；否则按既定确认流程继续。本文不改当前数据、协议、代码或阈值，不授权 test 推理，不代表已启动任何后续实验。

已有证据仅说明：V2 的 loss 对齐正确；低平均 completion loss 主要掩盖首动作判别错误。扩大 LoRA 模块后，旧 dev 回答增加但冒答也增加，不能仅凭此认定模型容量不足。[损失诊断](../v3/diagnostics/README.md)、[同预算容量对照](../v3/capacity-probe/comparison.json)、[配对 train/dev 诊断](../v3/diagnostics/capacity-comparison.json)均是已见数据上的探索证据，不能替代 V3.1 结果。

先做一次有界诊断：固定 seed 和 ID，从 train 按主题/套餐分层选 12 个完整组，比较第 1800、2400 步的自由生成；dev 使用已保存的完整结果。逐项列 action、value、引用集合、格式错误，并按日期、主题、冲突/一致性及 budget 配对汇总。仅对固定的分层小样本计算 teacher-forced 首动作 NLL 与字段 token 正确率。自由生成始终只接收原始公开消息；teacher forcing 的正确前缀仅用于离线诊断。以下数值是**下一轮诊断的工程触发条件，不是统计显著性标准或新的验收门槛**。

| 观察到的条件 | 可支持的解释与下一步 | 什么会推翻这个解释 |
| --- | --- | --- |
| train 严格成功或 answer 成功仍 <90%；1800→2400 的 train 首动作 NLL 降低 ≥10%，自由生成提升 ≥3 个百分点；dev 风险未同时恶化 | 仍有学习进展，先登记一个更充分训练的纯主任务对照；保留同一数据与模型，不同时换监督或扩大模型 | 新预算后训练动作不再改善，或回答增加只换来拒答退化。不能无限延长训练 |
| train answer <90%，且晚期自由生成变化 <1 个百分点、动作 NLL 改善 <5%；实现和数据审计均通过 | 可能是表示/优化受限，但**不是已证实的 0.5B 硬容量上限**。若错误不集中于少数可解释因素，优先比较本地 1.5B | 更大模型在匹配数据暴露下仍不提高 train 动作正确率；则“换大模型即可解决”被否定 |
| train 严格和 answer 均 ≥95%，dev 对应指标落后 ≥15 个百分点；错误跨主题/日期分散 | 优先扩大训练实体多样性，减少对 80 个训练实体及其组合的记忆 | 同预算更多独立实体未缩小差距，或 train 也同步下降；需要重新检验覆盖与预算，不直接声称泛化提升 |
| ≥60% 的动作错误集中在日期有效性、主题适用性或证据一致性；相应单因素配对正确率 <80%；正确 answer 前缀下值/引用 token 正确率 ≥99% | 优先增加针对该因素的训练期辅助证据监督，检验局部判别能否迁移到最终动作 | 辅助任务 dev 已学会，而原主任务的对应配对与七项指标没有改善；否定这次迁移机制 |
| answer 动作正确率 ≥95%，但严格 answer <80%，错误主要是值或引用集合（尤其 consensus 漏引第二篇） | 先检查目标、引用集合与 raw 输出截断；通过后针对集合聚合/引用训练，不先扩大模型或提高动作权重 | 错误实际上主要在 action，或只是低精度近并列样本；应返回动作判别诊断 |

日期/主题错误必须由匹配干预归因，不能只看变体名称：比较 `supported↔expired/future`、`conflict↔irrelevant_topic`、`conflict↔consensus` 的同预算双方；检查是否同时学会适用范围、有效期与一致事实。目标/引用检查使用独立生成记录和公开 observation 核对，只用于审计，不把规则判断注入推理。若出现标签错误或泄漏，应停止训练并另建有明确修订记录的数据版本，保留原失败结果。

三条路线每次只启动一条，并先登记预算与对照：

- **1.5B：** 使用官方 [Qwen2.5-1.5B-Instruct](https://huggingface.co/Qwen/Qwen2.5-1.5B-Instruct) 固定 revision，从其底模重新训练标准 LoRA；同 train、主任务暴露量、有效 batch、解码合同，对比现有 0.5B。同 rank 在不同模型上不代表同参数量，同样步数也不代表同算力，均如实记录。先在本机做 20 步 bf16、batch 1、梯度检查点的预检，实测内存和吞吐；本项目尚未验证它在此电脑上的完整训练成本，不提高内存水位强行运行。
- **辅助监督：** 从 train 实体派生单文档 scope/time/authority 标签；若错误集中于 consensus，则派生适用 ID 集合及事实一致性任务。先选一种，预登记 80% 主任务、20% 辅助的起点，与同总更新预算的纯主任务比较，报告主任务暴露量差异；辅助样本必须独立 schema/audit。只有迁移到原三字段自由生成才算有效。详见[现有方案](../v3/auxiliary-supervision-proposal.md)，不在推理增加 oracle 或修复输出。
- **实体多样性：** 保持 24 单元和因素分布，将 train 独立组由 80 扩为 240，与原 80 组在相同主任务样本暴露预算下比较；记录 token 和耗时差异。新实体必须与全部保留 dev/test 的实体并集隔离。不能把同实体换 ID、重复行或更多 epoch 当作新增多样性。

若条件重叠，先排除标签/实现错误，再按“局部因素集中→辅助监督；训练已拟合但 dev 落后→多样性；训练广泛停滞→1.5B”选择最小干预。若只有预算不足的证据，先做有上限的训练预算对照。新的线性学习率调度会改变前段轨迹，不能将不同 `max_steps` 的结果称为纯容量对照。

所有新运行仍只用本机和免费公开权重，不调用付费教师/API。追加开发轮次保留失败、配置与数据 SHA，dev 的反复使用明确标为适应性开发；只有全部七门槛通过的候选才能进入仍未使用的最终确认。任一路线若不能改善其指定错误且保持风险门槛，就停止该解释下的重复尝试，不同时堆叠三种改动后笼统宣称“优化成功”。
