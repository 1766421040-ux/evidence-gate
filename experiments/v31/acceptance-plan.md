# V3.1 验收补充：topic 作用域与证据一致性

V3.1 替代尚未用于模型确认的 V3 20 单元协议。触发原因是 [V3 train/dev 静态覆盖审计](../v3/train-dev-audit.md)：一个不匹配问题 topic、不比较官方事实值的公开输入规则可以在已见开发数据上严格全对。修订没有使用 V3 dev/test 模型预测，旧数据、协议、冻结记录和失败分析全部保留。实际冻结状态以本目录 `protocol.json / freeze.json / supersession.json` 为准；此文不报告模型成绩。

固定新 seed **20261030**、独立分区随机域和 `v31-{split}-gNNNN` 组名。main、v2、v3 所有 split 中实际出现的产品、干扰实体和恢复目录实体，与新 train/dev/test 全部隔离。每组保留十种语义的 budget 0/1 配对，增加四个单元，共 **24 单元**：

- `irrelevant_topic_b0 / _b1`：从对应 conflict 只改第二个官方文档的 topic，使其与问题不同；两篇仍当前有效、同产品和套餐、数值不同。应回答原事实，仅引用适用文档。错误 topic 在另外两类中按组平衡选取，社区、顺序和日期保持。
- `consensus_b0 / _b1`：从对应 conflict 只改第二个官方文档的值，使两篇适用证据一致。应回答并引用两个 ID，集合顺序不限。
- 现有 missing 的一半组保留 mixed-topic，另一半组让两个 official 都是同一个错误 topic；均没有适用官方证据。这样既不能用“任意 topic 不同就拒答”，也不能用“官方 topic 相同就当作匹配问题”。不新增变体。

恢复目录使用独立 ID；新增两情景的恢复事实与各自公开事实语义一致，引用集合按真实恢复 observation 重新计算。原日期、来源、数字、预算及 value_changed 单因素约束均保留。所有输入仍使用原 `messages_for`；不改模型 prompt，不改 `score / parse_prediction`。

| 分区 | 产品组 | 行数 | 可答 / 非可答 |
| --- | ---: | ---: | ---: |
| train | 80 | 1,920 | 960 / 960 |
| dev | 24 | 576 | 288 / 288 |
| test | 60 | 1,440 | 720 / 720 |

原七项阈值不变：严格成功 ≥85%，可答成功 ≥80%，四动作 macro F1 ≥0.80，整组全部正确 ≥50%，过度回答 ≤5%，格式合法 100%，已输出 answer 中无依据比例 ≤5%。风险门槛要求合法 answer 数至少 `ceil(0.8 × answerable)`；null/无 answer 不通过。主 test 对应严格成功至少 1,224/1,440、可答至少 576/720、完整组至少 30/60、过度回答最多 36/720、合法 answer 至少 576；dev 对应严格成功至少 490/576、可答至少 231/288、完整组至少 12/24、过度回答最多 14/288。

选择沿用 V3 的“先七项全过、再排序”：可答成功、整组成功、总体成功依次降序，已答风险升序，最后按预登记候选顺序。无合格候选就保存 `no_eligible_candidate` 并禁止 test。候选配置/预算仍由训练注册表在运行前登记；只在模型、协议与注册表指纹核验后做一次确认。失败如实保存，不在看过 test 后改门槛或重复挑 checkpoint。

既有严格集合引用计分已支持 consensus，无需改变评分口径。原摘要与历史评测保持兼容；`conflict → irrelevant_topic` 的 topic_filter、`conflict → consensus` 的 conflict_agreement 另做同预算配对报告，两侧都严格正确才通过。单独 pair 报告不能改写主摘要，规则分数不能替代模型结果。

构建先做 CPU schema、完整 24 单元、身份隔离、公共规则/恢复一致性、干预字段和捷径审计，再冻结数据与代码 SHA。主协议只覆盖有限合成语法，未自动纳入新措辞、多轮 Agent 或生产压力认证；新增这些范围须另行预先冻结，不能根据结果决定是否计分。
