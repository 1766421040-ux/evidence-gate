# 备用方案：只在训练期加入证据逐项判别任务

这是方案，不是已实现或已验证的改进。优先等待当前“同 V2 数据、扩展 LoRA 模块”的容量对照。root 的新增诊断表明动作部分约占 99.7% 的残余 NLL；这削弱了再提高动作 loss 权重的理由，不能把 token 数量少直接当成梯度不足。更少的训练样本也可能尚未拟合，因此不应先无条件增加辅助任务复杂度。

## 保持的边界

最终 Agent 仍接收原来的 system 和 public observation，仍直接生成三字段 `action/value/citations`。推理不增加第二次模型调用，不先执行规则判断，不把标签或正确引用塞进提示词，也不通过后处理替换模型动作。辅助任务只用于训练 LoRA，部署时使用同一组 LoRA 参数和原始推理模板。

辅助样本必须单独存储和声明 task kind，不能冒充当前 `messages_for` 合同下的主任务行；当前 trainer 的输入审计会正确拒绝这种混装，后续实现需要显式支持并分别审计训练任务，而不是关闭审计。

## 两种最小辅助任务

**A. 单文档适用性。** 输入只包含问题、as_of 与一篇原始文档，移除 budget。训练输出一个短的结构标签，例如：

```json
{"scope":"match","time":"expired","authority":"official","supports":false}
```

scope 必须同时匹配产品、套餐、主题；time 按当前 `[valid_from, valid_until)` 边界区分 valid/expired/future；authority 按真实 source 判断。辅助标签来自构造时记录的独立因素与可见文本逐项核对，不能从主任务 action 倒推。例如支持和冲突场景中的单篇官方文档都可能 `supports=true`，否则会把全局结果泄漏为局部标签。

**B. 无预算的证据集合状态。** 输入是原问题、as_of 和全部原始文档，仍移除 budget。输出：

```json
{"state":"sufficient|insufficient|need_plan","applicable_ids":[]}
```

sufficient 表示至少一篇适用的官方有效证据且其值一致；insufficient 包括缺失与冲突；need_plan 明确保留澄清条件。此处所有判断由模型学习生成，辅助任务的目标记录仅供训练。不能把这份正确状态在主任务推理时当作输入。`applicable_ids` 是逐文档判断的可审计对象，不代表只要有 ID 就足以回答；冲突时仍可能存在多个适用 ID。

先只做 A；如果 A 的 dev 适用性可学，而主任务冲突判断仍差，再考虑 B。不要一次叠加全部辅助任务后把提升归因于某一个环节。

## 如何与主任务混合而不制造新捷径

- 所有主任务、辅助任务从同一 train 产品组派生；dev/test 产品及其任何文档不进入辅助训练。主任务 split 和辅助 split 使用同一实体并集审计。
- scope/time/authority 因素必须交叉：同一个产品、文档位置、数值、日期模板不决定正确与否。存在“日期有效但错套餐”“套餐匹配但已过期”“社区说法吻合但不具权威性”等组合。
- 同一原始上下文的两个预算版本只在主任务中出现；辅助任务去掉预算后去重，避免把同一辅助输入重复计作新事实。
- 建议初始保持 80% 主任务、20% 单文档辅助。比例只是待注册的起点，不是已证明最优。保持原始主任务 completion 与 EOS 监督，不在主任务目标前加分析文本。
- 以标准多任务 SFT 描述这项工程干预，不声称新算法或新推理能力。

## 可证伪的比较

主对照使用同一新训练集、同一底模、同一 LoRA 配置和同一注册预算的纯主任务 SFT；辅助方案仅改变任务混合。保存实际主任务样本暴露量、总监督 token、输入 token、训练时间。主任务样本数与总计算预算不能同时天然相等，比较时必须说明取哪一种预算并列出差异。

如果希望证明收益来自“证据逐项监督”，再加一个相同比例的简单复制辅助任务：复制原文中的数字或 ID，不判断适用性。该对照区分更多训练/复制练习与证据判别，不是部署路径。个人电脑预算有限时可先做前两个，不提前声称机制已被因果隔离。

主要诊断依次是：

1. 单文档任务是否在未见产品 dev 上区分 scope/time/authority；仅辅助训练准确不能算通过。
2. 原始主任务的可答 budget0/1 成对不变率是否提高；最终答案与引用仍按原合同严格计分。
3. 过期/未来/错套餐/社区来源是否不再冒答，不能以 answer recall 换取风险上升。
4. 新的完整 dev 是否满足全部门槛；只有合格候选才进入从未推理的新 holdout。

若辅助任务学会而主任务动作无改进，就否定“该多任务迁移足以改善最终决策”的假设。若主任务训练样本仍不能拟合、辅助任务也差，应优先处理容量或实现问题，不能继续叠加监督任务。无论结果如何，不在推理时调用规则 oracle 来替模型过关。
