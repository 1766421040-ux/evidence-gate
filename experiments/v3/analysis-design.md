# V2 的可答失败诊断与 V3 最小改进建议

本记录由 CPU 文件分析、真实 tokenizer 统计与采样重放得到。没有加载模型权重、启动 GPU 或创建新模型预测。历史 V2 test 已经公开，下面只把它用作失败诊断；后续实验只能用 train/dev 调试，最终验证需另建从未推理的新 holdout。数据、代码和既有预测哈希见 [analysis-design.json](analysis-design.json)。

## 先确定失败发生在哪里

| 已有评测 | 可答中输出 answer | 其中数值与引用均正确 | 错误 search / abstain | 生成到长度上限 |
|---|---:|---:|---:|---:|
| dev 第 200 步 | 0/48 | 不适用 | 24 / 24 | 0 |
| dev 第 400 步 | 23/48 | 23/23 | 24 / 1 | 0 |
| dev 第 600 步 | 13/48 | 13/13 | 21 / 14 | 0 |
| 历史 test 选中 600 步 | 10/80 | 10/10 | 37 / 33 | 0 |

已观察到的可答失败全部发生在动作选择。不能由此推断“被拒答的样本强制 answer 后也一定能复制正确”，但现有证据不支持优先修 JSON、增加生成长度或重新训练引用格式。

400 到 600 步，13 条 dev 可答样本从正确 answer 退化为 abstain，只有 3 条从 search 恢复为 answer。最后 50 步平均训练 loss 从约 0.0347 降到 0.0263，因此“继续降低训练 loss”不是足够的验收依据。旧选择指标把 answer 下降与 abstain 上升平均：四动作严格成功宏平均仅由 0.767708 升至 0.773958，最终选到了可答更弱的 600 步。400 步也不能直接发布为达标模型，其 dev 冒答率为 16.67%，600 步为 8.33%，均超过 5%。

## 最强的剩余捷径

V2 消除了文档数量与注入短句有无的线索，但未消除以下两个文本模式。

1. **三篇文档都提到问题中的产品，只出现在 distractor。** 每个 train/dev 产品组各有一条，全部可答；没有过期、冲突或错套餐条件下的同模式反例。
2. **两篇 official 文档中的数值相同，只出现在 value_changed。** `changed` 同时被用作变更后的正确值和另一个套餐的值，使这个相等关系变成单向的可答标记。没有数值相同但主题、产品、套餐或日期不适用的负例。

一个完全不检查日期、不比较套餐的诊断分类器就能取得：

```text
缺少套餐 -> clarify
否则，三篇文档均提到问题产品 或 两篇 official 数值相同 -> answer
否则，budget > 0 -> search；budget = 0 -> abstain
```

| 数据 | 动作正确 | 可答动作召回 | 不可答误判 answer |
|---|---:|---:|---:|
| train | 960/1120 = 85.71% | 160/320 | 0/800 |
| dev | 144/168 = 85.71% | 24/48 | 0/120 |

这是动作分类诊断，不是答案与引用的严格成功成绩，也不是建议用于修补模型的后处理规则。它说明当前平均动作分数可被廉价文本线索支撑。第 600 步 dev 的 13 个可答成功中，8 个属于 distractor；supported 只有 1/12。历史 test 的 supported 与 value_changed 均为 0/20，9/10 个可答成功来自 distractor。这与剩余表面线索有关联，尚不能证明模型内部确切采用了上述分类器。

预算捷径也仍然很强。单看 train 的 budget=1 子集，400/600 是 search；budget=0 子集，320/520 是 abstain。加上缺套餐识别，即使完全忽略证据也可有 800/1120 = 71.43% 动作正确。该规则与第 200/400/600 步 dev 实际动作的吻合度分别为 161/168、125/168、145/168；与历史 test 为 264/280。每个产品组的可答与 clarify 情境只使用固定的一种预算，因此缺乏“同一份充分证据在两种预算下都要回答”的组内不变性监督。

## 训练代码与实际采样

逐步调用训练器原有 `_next_indices` 重放 seed 42，并用真实 tokenizer 重算所有监督 token，得到的监督总数与保存的 metrics 完全相同。

| 步数 | 样本位置 | 不同训练行 | answer 样本位置 | answer 的预算 0 / 1 |
|---|---:|---:|---:|---:|
| 200 | 800 | 800 | 220 | 113 / 107 |
| 400 | 1600 | 1120 | 454 | 222 / 232 |
| 600 | 2400 | 1120 | 687 | 347 / 340 |

600 步时 960 行出现两次、160 行出现三次，没有遗漏 answer 类或其某一预算。当前瓶颈不是采样器只抽取了拒答样本。1120 个 train 和 168 个 dev target 均与公开 observation 规则一致；提示词投影一致，未发现相同提示对应矛盾标签。

代码检查未发现监督错位、截断或训练/推理模板不一致：训练显式验证 prompt 是完整 assistant 序列的前缀；只监督 assistant 与 EOS；padding 标签为 -100；梯度累积按各 microbatch 的实际监督 token 数加权；推理使用同一个底模 tokenizer 与 chat template。训练右填充、生成左填充是标准路径，现有静态证据不能把它认定为本次失败原因。若怀疑数值或批量效应，可在 dev 上做少量 batch 1/4 一致性诊断，不改变正式评测口径。

## Token 监督解释

600 步共有 38,926 个监督 token；结构与 chat 结束部分约占 75.75%，动作字符串 token 占 10.11%，数值与引用内容合计约占 14.14%。每个样本的首个动作决策仅有一个 token，合计 2,400 个，约占 6.17%。这是 token 暴露统计，不是梯度贡献测量。

`answer` 和 `search` 各为一个 tokenizer token，`clarify` 是两个，`abstain` 是三个。短 JSON 的绝大部分内容在 teacher forcing 下十分容易；“最终 loss 很低”可以与首个动作的泛化薄弱同时存在。

**不能把 3.38% 的监督/输入比例误解释成 prompt 稀释了 loss。** prompt 已被 mask，loss 的分母是监督 token。answer 只占实际样本位置的 28.63%，但因完成文本更长，占监督 token 的 38.85%。因此单纯宣称“答案 token 太少”也不准确。现在更应关注证据判断所需的对比样本和首个动作信号。

## 最值得先做的本机改进

1. **先修数据中的具体混杂，不改标签来迎合模型。** 社区文档是否提到当前产品应独立于动作/变体；给“全篇同产品”的过期、冲突、错套餐情境加入反例。其他套餐值独立生成，并在可答和不可答情境都覆盖相等与不等；value_changed 不要总等于其他套餐值。保证可答样本并非靠某个文本模式才能出现。
2. **显式覆盖充分证据的预算不变性。** 同一产品、证据、日期、排序下同时保留 budget 0 与 1 的 answer，以及两种预算的 clarify；无充分证据仍分别 search/abstain。若增加变体数量，先冻结新的成组计分协议，不能沿用“14 变体全部正确”的旧名称而悄悄更换分母。
3. **让训练与 dev 覆盖可区分的对照。** 有效官方证据/错误套餐/错产品/过期/未来/冲突，应只改变必要字段；文档顺序、社区相关性、数值相等性作为独立因素。dev 按预算、有效证据位置和日期状态分层；旧 dev 仅 4/48 个可答样本的证据在中间位置，不能把位置与预算共同造成的现象误称为纯位置缺陷。
4. **先用标准 SFT 验证数据修正。** 保留原模型、输出协议与损失，比较同一固定训练预算下的 dev。若改采样，可把一批组织为充分证据预算对与其不可答最小对；这改变了训练分布，不能称为新损失或声称单独证明“成组关系”的收益。不得用 contract_rule 替换模型动作后再声称模型达标。
5. **如动作仍差，再做一个针对性对照。** 可比较普通 CE 与动作首 token 加权 CE，或单独的证据状态辅助任务；两者都必须在相同数据、步数下比较，并继续测冒答。它们是候选干预，目前没有收益证据。由于已生成答案的复制表现很好，不优先扩大 max_new_tokens、强化 JSON 或增加引用修复。
6. **选模先满足硬门槛，再排序。** 必须同时考虑可答成功和冒答；旧的宏平均允许两者相互抵偿。任何 dev 候选未过门槛时都保留“未达标”，不进入新鲜 test，也不以 loss 最低作为替代。

可区分原因的最小 dev 诊断是：对固定的充分证据只翻转预算；只改社区是否提及问题产品；只改无关官方数值是否与正确值相同；只置换文档位置。分别记录动作不变率，并保留答案/引用严格成功。这些额外 dev 观察必须标为开发诊断，而非最终测试。若预算翻转显著改变答案，优先修条件不变性；若社区相关性决定答案，优先修该模式反例；若这些均稳定但日期样本失败，再针对日期边界增加监督。

## 证据边界

当前没有完成任何 V3 训练或新测试。不能保证上述候选一定达到门槛，也不能根据历史 test 再挑一个模型并称为独立验证。新 holdout 产品应与 main、V2 以及所有 V3 开发数据的实体并集隔离；旧文件与发布结果保持原样。现有精确规则仍可解决固定语法，项目的意义是训练与诊断闭环，而不是宣称 SFT 在该窄任务上优于规则。
